# Migrating to Swarm 0.7.0

0.7.0 is a breaking release. Each section below is self-contained and covers one
change set.

## AgentConfiguration consolidation

`AgentConfiguration` had two or three ways to set the same thing. Each concern
now has one source of truth.

### Sampling lives in `modelSettings`

`temperature`, `maxTokens`, and `stopSequences` are no longer stored properties
on `AgentConfiguration`. `modelSettings` is now non-optional
(`ModelSettings`, default `ModelSettings()`), and unset fields fall back to the
`InferenceOptions` defaults. The fluent `.temperature(_:)`, `.maxTokens(_:)`,
and `.stopSequences(_:)` builders still exist; they write into `modelSettings`.

| 0.6 | 0.7 |
|---|---|
| `AgentConfiguration(temperature: 0.2, maxTokens: 500, stopSequences: ["END"])` | `AgentConfiguration(modelSettings: ModelSettings(temperature: 0.2, maxTokens: 500, stopSequences: ["END"]))` |
| `config.temperature` / `config.maxTokens` / `config.stopSequences` | `config.modelSettings.temperature` / `.maxTokens` / `.stopSequences` (optional; `nil` means provider default) |
| `config.temperature = 0.2` | `config.modelSettings.temperature = 0.2` or `config = config.temperature(0.2)` |
| `config.modelSettings?.topP` | `config.modelSettings.topP` |
| `.modelSettings(nil)` | `.modelSettings(ModelSettings())` |

Behavior change: in 0.6, when `modelSettings` was set, its sampling fields
silently overrode the separate `temperature`/`maxTokens`/`stopSequences`
values. In 0.7 there is only one value. `.modelSettings(_:)` still keeps
sampling values set by earlier `.temperature`/`.maxTokens`/`.stopSequences`
calls when the incoming settings leave those fields `nil`, and non-`nil` fields
in the incoming settings win, as in 0.6. A sampling builder called after
`.modelSettings(_:)` now overwrites that field instead of being ignored. Out-of-range
temperatures written through the builders now clamp to `0...2` (the `ModelSettings`
rule) instead of resetting to `1.0`.

### `contextProfile` is the only context knob

`ContextMode`, `AgentConfiguration.contextMode`, `.contextMode(_:)`, and the
`effectiveContextProfile` resolver are removed. `.strict4k` was only a shortcut
for the strict 4K profile.

| 0.6 | 0.7 |
|---|---|
| `.contextMode(.strict4k)` / `AgentConfiguration(contextMode: .strict4k)` | `.contextProfile(.strict4k)` / `AgentConfiguration(contextProfile: .strict4k)` |
| `.contextMode(.adaptive)` | Remove it; `contextProfile` is used as-is. |
| `config.effectiveContextProfile` | `config.contextProfile` |

`AgentConfiguration.onDeviceDefault` on iOS/tvOS/watchOS/visionOS now sets
`contextProfile: .strict4k` directly; the resulting budget is unchanged.

### Response continuation is per run

The configuration-level `previousResponseId` (property, init parameter, and
`.previousResponseId(_:)` builder) is removed. A pinned response ID on a
reusable configuration applied to every run of every agent built from it,
which is rarely what you want. Pass it per run instead:

```swift
// 0.6
let agent = try Agent(configuration: .default.previousResponseId(lastID), ...)
let response = try await agent.runWithResponse("Make it 3 days")

// 0.7
let response = try await agent.runWithResponse("Make it 3 days", continuing: lastID)
```

`autoPreviousResponseId(true)` is unchanged and still chains IDs per session.
An explicit `continuing:` ID wins over auto tracking for that one run and is
still dropped for providers without `.responseContinuation`.

### Durable checkpoints

Workflow signatures keep the 0.6 layout, so checkpoints written by 0.6 resume
unchanged when the agent used the default configuration, the
`temperature`/`maxTokens`/`stopSequences` builders or init parameters, or
non-empty `modelSettings` values (for example `topP` or `toolChoice` set) that
leave those three fields unset. Resume reports a workflow signature mismatch
(start a new run) when the 0.6 agent used:

- `contextMode: .strict4k`, including `AgentConfiguration.onDeviceDefault` on iOS-family platforms;
- `modelSettings` that set `temperature`, `maxTokens`, or `stopSequences`
  (including the `.precise`, `.balanced`, and `.creative` presets);
- an explicitly empty `modelSettings` (`.modelSettings(ModelSettings())` or
  `.modelSettings(.default)`), which 0.7 signs the same as no model settings;
- a configuration-level `previousResponseId`.
